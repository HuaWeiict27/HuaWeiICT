# 第一周具体工作（2026-10-12—10-18）

## 本周唯一交付物

**《赛题2实施方案书 v1》**

一句话定义：

> 用一份不超过 10 页的方案书，锁定“为谁解决什么问题、为什么必须用 Agent、用 AgentArts 怎么实现、2个月如何做完”。

本周不追求写代码，只允许做能验证选题和需求的最小技术试验。禁止直接开始搭完整产品。

## 本周目标

- 把赛题2、评分项、提交要求整理成可核对的清单。
- 调研 5—10 位真实用户，拿到真实痛点证据。
- 从至少 10 个候选方向中筛出 3 个。
- 用评分表选出 **1 个主选题 + 1 个备选**。
- 产出《赛题2实施方案书 v1》和 10 分钟汇报。
- 让指导老师确认：方向可行、范围可控、2个月能完成。

## 建议本周三候选

如果优先考虑教育方向，建议从以下三类中产生候选：

1. **LabMate 实验课智能助教 Agent**
   - 微电子同学优势最大
   - AgentArts 能力点：图像识别、实验手册 RAG、故障树、安全审核、多 Agent
2. **教师备课与分层作业 Agent**
   - 最容易在 2 个月内完成
   - AgentArts 能力点：课标 RAG、分层出题、评分量表、多 Agent
3. **职业技能陪练 Agent**
   - 商业化最清晰
   - AgentArts 能力点：角色扮演、评分、教练、多场景工作流

其他备选：冰箱食材管家、家电故障诊断、老人陪诊。

## Day 3｜周三 10/14：集中发散选题

**目标**：从至少 10 个点子收敛到 3 个候选。

### 全员
每人独立写 5 个贴近生活的选题，不能讨论，避免互相影响。

选题必须写清：

- 目标用户
- 高频痛点
- 现有替代方案
- 输入和输出
- 为什么需要 Agent
- 需要什么数据和工具
- 现场怎么演示

### A
- 从技术角度筛掉“2个月做不完”和“只能做硬件”的选题。
- 检查每个选题是否真的用到 AgentArts 的构建、编排、知识库、工具、多 Agent 或评测。

### B
- 从用户角度筛掉伪需求和低频需求。
- 检查是否能找到 5 位以上真实用户。

### C
- 从数据和硬件角度筛掉无数据、无工具、难演示的选题。
- 对教育/实验方向，优先评估 LabMate 的可行性。

**收敛规则**
- 10—15 个点子 → 3 个候选。
- 每个候选必须能用一句话说清。
- 不保留“大而全”的平台型想法。

**周三小时交付**
- 3 个候选场景卡片
- 每个场景的风险清单

## Day 4｜周四 10/15：用户调研与可行性验证

**目标**：拿到真实用户证据，不靠想象选题。

### B
- 访谈 5—8 位目标用户，每人 10—15 分钟。
- 记录原话，重点问：
  - 最近一次遇到这个问题是什么时候？
  - 现在怎么解决？
  - 最烦的是哪一步？
  - 如果有一个 Agent，最希望它做什么？
  - 愿不愿意用？愿不愿意付费？

### A
- 对 3 个候选做技术可行性评审。
- 画出每个候选的最小闭环：输入 → Agent → 工具/知识库 → 输出。
- 估算 2 个月实现难度。

### C
- 检查数据来源、知识库构建难度、工具/API 可获得性。
- 检查隐私、安全、版权和合规风险。
- 做 AgentArts 最小功能冒烟测试：新建 Agent、加知识库、调一个工具。

**周三小时交付**
- 用户访谈纪要
- 3 个候选的技术可行性对比
- AgentArts 冒烟测试记录

**Gate 2**：如果某个选题找不到真实用户或拿不到数据，直接淘汰。

## Day 5｜周五 10/16：评分、决策、写一页纸

**目标**：选定 1 个主选题 + 1 个备选，完成一页纸方案。

### 全员评分
每个候选按 7 项打分，每项 1—5 分：

1. 痛点强度
2. Agent 必要性
3. 数据可得性
4. 2个月可行性
5. 演示效果
6. 商业价值
7. 合规安全

### 决策规则
- 最高分作为主选题。
- 第二名作为备选。
- 如果第一名和第二名差距小于 2 分，优先选更容易在 2 个月完成的。
- 不允许三个人各选一个，必须形成团队结论。

### A
- 画出主选题的上下文图和最小闭环。
- 初步确定 Agent、工具、知识库、MCP/Skill 的边界。

### B
- 写一页纸方案：
  - 项目名
  - 目标用户
  - 痛点
  - 解决方案
  - 核心流程
  - 数据来源
  - 技术亮点
  - 预期效果
  - 风险

### C
- 验证数据与评测方案。
- 设计 20 条测试用例的框架。
- 给出 AgentArts 能力使用清单。

**周三小时交付**
- 《一页纸方案》
- 主选题 + 备选结论
- 最小闭环图

# 第一周验收标准

必须同时满足：

- [ ] 官方赛题、评分项、提交物和禁止项已逐条覆盖。
- [ ] 至少访谈 5 位真实用户，有原话和证据。
- [ ] 至少比较 3 个候选方向，有评分表。
- [ ] 明确 1 个主选题 + 1 个备选。
- [ ] 能用一句话说清“为谁解决什么问题”。
- [ ] 能解释“为什么必须是 Agent，而不是普通问答机器人”。
- [ ] 能画出最小闭环：输入 → Agent → 工具/知识库 → 输出。
- [ ] 明确数据来源、工具来源、合规风险。
- [ ] 指导老师确认方向可行。
- [ ] 第二周可以开始架构设计，不依赖关键未知项。

# 第一周禁止事项

- 禁止开始做完整前端。
- 禁止大规模写业务代码。
- 禁止三个人各选一个方向。
- 禁止用未经授权的数据、图片、教材或医疗/金融数据。
- 禁止为了“技术炫技”加入多 Agent、MCP、硬件而说不清价值。
- 禁止把“做个聊天机器人”当成最终成果。
