# 成果拆解：每周一个唯一交付任务

> 规则：每周只认一个“唯一交付物”。调研、编码、实验、文档都可以做，但都必须服务于当周交付物；周五 Demo Day 只验收这一件。
>
> 默认周期：2026-10-12—2026-12-06，共 8 周。

## 总览

| 周次 | 日期 | 每周唯一交付物 | 最终用途 |
|---|---|---|---|
| W1 | 10/12—10/18 | 《赛题2实施方案书 v1》 | 锁定选题与需求 |
| W2 | 10/19—10/25 | 《Agent系统架构设计书 v1》 | 锁定技术路线 |
| W3 | 10/26—11/1 | 《AgentArts最小闭环Demo v0.1》 | 证明平台可跑通 |
| W4 | 11/2—11/8 | 《MVP端到端演示包 v0.5》 | 证明业务闭环 |
| W5 | 11/9—11/15 | 《核心能力增强版 v0.8》 | 体现技术深度 |
| W6 | 11/16—11/22 | 《评测与优化报告 v1.0》 | 用数据证明有效 |
| W7 | 11/23—11/29 | 《大赛交付物完整包 v1.0》 | 形成可提交版本 |
| W8 | 11/30—12/6 | 《最终提交包与答辩包 vFinal》 | 完成提交和答辩准备 |

## W1（10/12—10/18）
### 唯一交付物：《赛题2实施方案书 v1》

**交付内容**

- 赛题2要求与评分项逐条对照表
- 3 个候选场景及六维评分
- 1 个主选题 + 1 个备选
- 目标用户、痛点、核心流程、数据来源、风险
- 一页纸项目定位

**完成定义**

- 每个“必须项”都能在方案书中找到对应位置。
- 主选题能用一句话说清：为谁，解决什么问题，为什么必须用 Agent。
- 三人对主选题无重大分歧。

**负责人**

- B 主笔；A 负责赛题/评分项；C 负责技术可行性论证。

**周五验收**

- 不通过：继续讨论选题，不进入架构设计。

---

## W2（10/19—10/25）
### 唯一交付物：《Agent系统架构设计书 v1》

**交付内容**

- 上下文图、组件图、数据流图、时序图
- 单 Agent / 工作流 / 多 Agent 的选型结论
- 工具、知识库、记忆、人机确认边界
- 接口清单、数据权限、部署方式
- MVP 功能冻结清单

**完成定义**

- 架构能支撑 W1 定的主流程。
- 每个工具都有输入、输出、失败处理。
- MVP 范围可在 W3—W4 两周内实现。

**负责人**

- A 主笔；C 负责评测与工具可行性；B 负责用户流程和产品边界。

**周五验收**

- 不通过：砍功能、缩范围，重新确认 MVP。

---

## W3（10/26—11/1）
### 唯一交付物：《AgentArts最小闭环Demo v0.1》

**交付内容**

- 一个真实输入
- Agent 规划与一次模型调用
- 至少 1 个工具或知识库调用
- 一个结构化输出
- 一段可复现的录屏

**完成定义**

- 在 AgentArts 上能连续跑通 5 次。
- 有环境配置说明和失败日志。
- 不是“伪页面截图”，而是真实调用链路。

**负责人**

- A 主责 AgentArts 和工具链；B 准备样例输入与演示脚本；C 做基础评测与故障记录。

**周五验收**

- 不通过：W4 不扩展功能，先修通最小链路。

---

## W4（11/2—11/8）
### 唯一交付物：《MVP端到端演示包 v0.5》

**交付内容**

- 用户输入 → Agent → 工具/知识库 → 结果 → 用户确认
- 可视化 Demo 页面或可操作界面
- 接口文档、启动说明、测试记录
- 10 条真实用例的运行结果

**完成定义**

- 真实流程连续 10 次成功，成功率不低于 80%。
- 演示路径固定、可复现、可回退。
- 至少 3 位外部用户体验并留下反馈。

**负责人**

- A 主责 Agent 编排与后端；B 主责界面与演示；C 主责测试记录与问题定位。

**周五验收**

- 不通过：暂停加功能，优先修复主流程。

---

## W5（11/9—11/15）
### 唯一交付物：《核心能力增强版 v0.8》

**交付内容**

- 知识库/RAG 接入与引用溯源
- 1—3 个必要的 Skill / MCP / 插件
- 视需要加入多 Agent 协作
- 安全、权限、异常兜底
- 增强前后的对比记录

**完成定义**

- 每项增强都有明确目的，不做“技术堆砌”。
- 相比 v0.5 至少一项核心指标有可量化提升。
- 知识库来源、许可、脱敏方式可说明。

**负责人**

- A 主责插件/MCP/多 Agent；C 主责知识库与评测；B 主责用户体验与文档。

**周五验收**

- 不通过：回退无收益模块，保留简单可靠方案。

---

## W6（11/16—11/22）
### 唯一交付物：《评测与优化报告 v1.0》

**交付内容**

- 评测集：正常、边界、对抗、幻觉、工具失败、越权
- 指标：成功率、正确率、引用命中率、时延、成本、人工介入率
- 消融实验：无 RAG vs 有 RAG、单 Agent vs 多 Agent
- 性能、成本、安全优化结论
- 局限与失败案例分析

**完成定义**

- 所有结论都有数据、配置和可复现命令。
- 至少完成 1 组有效消融实验。
- 评委能看懂“为什么有效、代价是什么”。

**负责人**

- C 主责评测与消融；A 主责性能成本优化；B 主责图表与报告。

**周五验收**

- 不通过：不得进入最终交付阶段。

---

## W7（11/23—11/29）
### 唯一交付物：《大赛交付物完整包 v1.0》

**交付内容**

- 技术文档终稿
- 可运行代码与 README
- 演示视频初版
- 答辩 PPT 初版
- 官方评分项逐条自查表

**完成定义**

- 三项核心材料齐全：技术文档、代码文件、演示视频。
- 按官方格式和命名要求整理。
- 团队成员之外的人可按 README 复现。

**负责人**

- B 主责文档、视频、PPT；A 主责代码与复现；C 主责评测证据与安全说明。

**周五验收**

- 不通过：周末集中修复，不新增功能。

---

## W8（11/30—12/6）
### 唯一交付物：《最终提交包与答辩包 vFinal》

**交付内容**

- 最终技术文档、代码、演示视频
- 答辩 PPT、讲稿、问答库
- 离线演示包、备用录屏、故障预案
- 提交回执截图、云端与本地双重备份

**完成定义**

- 按官方提交清单 100% 核验通过。
- 完成 3 次完整彩排：技术演示、评委问答、断网降级。
- 主讲、演示、补答三人分工明确。

**负责人**

- 三人共同负责；A 负责技术环境；B 负责材料与表达；C 负责风险问答与故障演练。

**周五验收**

- 完成提交；
- 输出一份复盘报告，沉淀可复用模板。
