# 风险清单、评分自查与项目管理模板

## 一、高风险清单

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 赛题2详细附件拿不到或理解偏差 | 中 | 高 | 第0周内向老师/组委会确认；先按官方总要求做，拿到附件后逐条校准 |
| 三人都是新生，技术深度不足 | 高 | 高 | 范围砍到一条主流程；用 AgentArts 低代码能力换时间；每周导师评审 |
| AgentArts 账号/算力/公测权限未开通 | 中 | 高 | 第0周申请；准备本地替代 Demo（LangChain/Agents SDK）作为备份 |
| 多 Agent 堆叠但无收益 | 中 | 中 | 先单 Agent + 工具 + RAG；只有量化提升才引入多 Agent |
| 数据隐私/版权/合规问题 | 中 | 高 | 只用公开/授权数据；脱敏；记录来源与许可；安全测试 |
| 模型幻觉导致演示翻车 | 高 | 高 | 引用溯源、规则校验、人工确认、固定演示数据、离线备份视频 |
| 2个月做不完 | 中 | 高 | 第1周冻结范围；每周能演示；砍功能不砍主线 |
| 分工不均或单点故障 | 中 | 中 | 主责+备份；每人都有代码产出；Git 可追溯 |
| 现场网络/云服务故障 | 中 | 高 | 本地缓存、离线包、录屏备份、降级演示方案 |

## 四、答辩问答准备方向

1. 为什么必须是 Agent，而不是普通脚本/单次大模型调用？
2. 为什么选择 AgentArts？用了哪些平台能力？
3. 知识库数据从哪来？如何保证准确、隐私、版权？
4. 如何防止幻觉和工具调用失败？
5. 多 Agent 相比单 Agent 的量化提升是什么？
6. 成本、时延、并发如何？
7. 商业化路径、目标客户、付费意愿如何？
8. 创新点与现有竞品的差异是什么？
9. 如果数据/模型/网络不可用，系统如何降级？
10. 2个月后如何继续迭代？
