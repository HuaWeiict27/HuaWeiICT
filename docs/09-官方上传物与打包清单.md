# 创新赛赛题2：到底要上传什么

## 一、先看官方硬性要求

依据《华为ICT大赛2026-2027手册》：

> 创新赛采用初赛—中国总决赛—全球总决赛三级赛制，参赛队伍需要提交相关**技术文档、代码文件和演示视频等相关材料**，并在中国总决赛和全球总决赛参与**现场演示答辩**。

因此，官方已明确的成果不是只有一份方案书，而是至少三类：

1. **技术文档**
2. **代码文件**
3. **演示视频**

平台入口名称：

> Talent 平台 → 我的大赛 → **作品及创意方案上传管理**
> 前端路径：`/ict-contest/works-upload`

最终上传页面的具体字段、格式、大小和截止时间，以 Talent 平台当前显示为准。官方手册没有公开更细的模板和文件名规范。

另外，入围中国总决赛/全球总决赛后，官方还要求发布作品分享帖：

> 在华为云开发者社区（Link）或其他社媒平台发布作品分享帖。

## 二、每个阶段上传什么

| 阶段 | 官方要求 | 建议准备 | 说明 |
|---|---|---|---|
| 初赛 | 技术文档、代码文件、演示视频等 | 技术文档PDF、代码压缩包/仓库链接、演示视频、复现说明 | 核心是证明方案真实可运行 |
| 中国总决赛 | 现场演示答辩 | 更新版文档、代码、视频、PPT、现场演示环境、离线备份 | 线上材料可能需重新上传/更新 |
| 全球总决赛 | 现场演示答辩 | 同上，视通知准备英文版材料、英文讲稿和演示 | 语言和格式以官方通知为准 |
| 入围分享要求 | 华为云开发者社区或社媒分享帖 | 分享帖正文、链接、截图 | 不是替代文档/代码/视频，而是额外传播要求 |

## 三、技术文档建议包含什么

建议输出 PDF，建议命名为：

`01_技术文档_队伍名_赛题2.pdf`

目录建议：

1. 封面：大赛名称、赛道、赛题编号、作品名、队伍名、学校、成员、指导老师、联系方式
2. 摘要：一句话说明解决什么问题、用了什么 Agent、效果如何
3. 背景与痛点：目标用户、现有方案、真实调研证据
4. 需求分析：功能需求、非功能需求、边界条件
5. 总体方案：系统架构图、数据流图、Agent 交互时序图
6. AgentArts 使用说明：Agent 编排、工作流、知识库、插件、MCP、Skill、记忆、发布
7. 核心功能：逐项说明输入、处理、输出、异常处理
8. 数据与知识库：来源、清洗、切分、Embedding、检索、引用溯源、合规说明
9. 关键实现：代码结构、接口、模型配置、提示词策略、工具调用
10. 评测与效果：测试集、指标、消融实验、对比结果、失败案例
11. 创新点：与普通 Chatbot/工作流相比的创新在哪里
12. 商业与落地：目标客户、成本、部署方式、商业模式
13. 局限与未来工作
14. 附录：参考资料、开源许可、复现说明

重点：不要只写“我们用了 AI”，要写清“为什么必须是 Agent、AgentArts 用在哪些环节、效果如何量化”。

## 四、代码文件建议包含什么

如果平台支持仓库链接，建议同时提交：

- Git 仓库链接（GitHub/Gitee 等）
- 代码压缩包备份

推荐压缩包命名：

`02_代码_队伍名_赛题2.zip`

压缩包内建议：

```text
project/
├── README.md                 # 项目说明、架构、启动方式、演示路径
├── requirements.txt          # Python依赖
├── pyproject.toml            # 可选
├── .env.example              # 环境变量示例，不放真实密钥
├── config/
│   └── config.example.yaml
├── src/
│   ├── agents/
│   ├── tools/
│   ├── knowledge_base/
│   ├── api/
│   └── ui/
├── prompts/
├── data/
│   └── sample/               # 可公开的样例数据
├── eval/
│   ├── test_cases.jsonl
│   └── results/
├── docs/
│   ├── architecture.md
│   ├── api.md
│   └── deployment.md
├── scripts/
│   ├── setup.sh
│   └── run_demo.sh
├── tests/
├── LICENSE
└── .gitignore
```

代码包中必须：

- [ ] 不含云账号密钥、Token、密码、个人隐私数据
- [ ] 有 README 和一键启动/复现说明
- [ ] 有样例输入和演示路径
- [ ] 有 AgentArts 配置说明、截图或导出文件
- [ ] 有知识库构建脚本
- [ ] 有 Skill/MCP/插件说明
- [ ] 有评测脚本和测试用例
- [ ] 依赖版本明确
- [ ] 代码可运行，不是只放几个片段

## 五、演示视频建议包含什么

建议命名：

`03_演示视频_队伍名_赛题2.mp4`

官方手册没有在公开页写死时长。若报名页/上传页给了时限，以页面为准。没有明确时限时，建议准备：

- 主版本：3—5 分钟
- 备份版本：8—10 分钟
- 极简版：90 秒

视频结构：

1. 10—20 秒：真实问题与目标用户
2. 20—40 秒：AgentArts 方案总览
3. 1—2 分钟：完整操作演示
4. 30—60 秒：知识库、工具、MCP/Skill、多 Agent 等技术亮点
5. 30—60 秒：评测数据与价值
6. 10—20 秒：商业价值与总结

视频必须展示：

- [ ] 真实输入，不只是 PPT
- [ ] AgentArts 平台中的 Agent/工作流
- [ ] 工具或知识库真实调用
- [ ] 多轮交互和异常兜底
- [ ] 最终结果和可量化效果
- [ ] 字幕和清晰配音
- [ ] 不出现个人隐私、密钥、违规内容

## 六、中国总决赛/全球总决赛还要准备什么

官方要求**现场演示答辩**，所以除了线上上传材料，还要准备：

- 答辩 PPT（建议 10—15 页，另有 3 分钟/8 分钟两版讲稿）
- 现场演示环境
- 离线演示包
- 备用录屏
- 代码冻结版本
- 故障预案：断网、模型超时、工具失败、数据异常
- 问答库：创新性、技术架构、AgentArts 使用、评测、隐私、安全、商业价值
- 三人分工：主讲、现场操作、技术补答

## 八、一句话结论

**初赛必须上传的核心成果是：技术文档 + 代码文件 + 演示视频。**  
中国总决赛和全球总决赛还要现场演示答辩；入围后还要发布作品分享帖。平台具体字段、模板和截止时间，以 Talent 平台“作品及创意方案上传管理”页面为准。
