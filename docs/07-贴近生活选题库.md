# 赛题2贴近生活选题库

## 一、筛选标准

一个好选题必须同时满足：

1. **真实高频**：身边人真的会遇到，最好你能找到 5—10 位目标用户。
2. **Agent 必要性**：不是简单问答，而是需要规划、工具调用、知识库、记忆或多 Agent 协作。
3. **数据可得**：2 个月内能拿到或构造数据，不依赖难以申请的行业数据。
4. **可演示**：现场 3—5 分钟能看懂输入、过程、输出和价值。
5. **可量化**：能证明省时间、省钱、降低风险或提升体验。
6. **有商业闭环**：能说清谁付费、为什么付费、如何规模化。
7. **安全合规**：不碰高风险医疗诊断、金融投资建议、违法维修等红线。

## 四、优先推荐：三个最适合你们团队的方案

### 推荐一：家电说明书与故障诊断 Agent（首选）

**项目名建议**：电器管家 / 家电Doctor

**场景**

家里洗衣机不脱水、路由器亮红灯、空调显示故障码，普通人第一反应是搜短视频、问客服、找维修，信息碎、被坑概率高。用户拍铭牌/故障灯/说明书，Agent 用自然语言问诊，给出安全的自检步骤、可能原因、是否在保修期、是否需要报修。

**用户**

- 刚租房/刚搬家的年轻人
- 不会看说明书的家庭用户
- 需要给父母远程指导的子女
- 小家电维修店/售后服务平台

**Agent设计**

- 识别 Agent：识别品牌、型号、故障码、指示灯状态。
- 诊断 Agent：结合手册 RAG + 故障树，逐层追问。
- 安全审核 Agent：判断是否属于高压/燃气/拆机等危险操作，危险场景直接阻止并转人工。
- 服务 Agent：查保修、找附近售后、生成报修描述和费用预估。

**工具/Skill/MCP**

- 说明书知识库：公开说明书 PDF + 自建故障案例库。
- 图像识别工具：上传故障灯/铭牌/错误码截图。
- 故障树工具：用 JSON/YAML 配置“症状 → 可能原因 → 检查步骤”。
- 保修/售后查询工具：先用模拟数据，后期接官方 API。
- 报修单生成工具：输出标准描述、照片清单、预约时间。

**为什么适合你们**

- 贴近生活，评委一听就懂。
- 微电子同学可以负责故障树、器件知识、传感/电路安全边界。
- 软工同学负责 Agent 编排、RAG、工具和前端。
- 演示效果强：拍一张故障灯照片，Agent 连续追问并给出排查步骤。

**安全边界**

- 不指导拆机、带电操作、燃气设备维修。
- 高风险场景只做“断电/停用/联系专业人员”建议。
- 所有诊断结果标注“非官方维修结论”。

**商业价值**

- 售后服务导流、维修报价透明化、家电保险、耗材/配件推荐、品牌客服降本。

**2个月MVP**

- 选 3 类家电：洗衣机、路由器、空调。
- 每类 20 个故障案例，共 60 条评测集。
- 跑通“图片/文字输入 → 识别 → 追问 → 诊断 → 安全审核 → 报修单”闭环。
- 对比“无手册RAG”和“有手册RAG”的诊断准确率。

### 推荐二：家庭冰箱食材管家 Agent（最容易做完）

**项目名建议**：今晚吃啥 / 冰箱管家

**场景**

打开冰箱不知道吃什么，食材快过期又不想浪费。用户拍冰箱照片或输入现有食材，Agent 结合口味、人数、健身目标、过敏原，推荐今晚菜谱，列出缺少的食材和购物清单。

**Agent设计**

- 识别 Agent：识别食材、数量、保质期。
- 菜谱 Agent：检索菜谱知识库，生成 3 个方案。
- 营养 Agent：计算热量、蛋白质、过敏原。
- 采购 Agent：生成购物清单和预算。
- 记忆：记住家庭成员口味、过敏原、忌口。

**工具/Skill/MCP**

- 食材图像识别
- 菜谱/营养知识库
- 过期提醒
- 购物清单生成
- 家庭偏好记忆

**优势**

- 2个月完成概率最高。
- 演示非常直观：拍照 → 推荐 → 菜谱 → 购物清单。
- 商业闭环清楚：生鲜电商、食谱平台、厨房电器。

**风险**

- 图像识别准确率可能不稳定；可用“拍照 + 手动修正”降低风险。
- 不要做医疗营养建议，只做一般饮食参考。

### 推荐三：家庭能耗与电费优化 Agent（微电子最强）

**项目名建议**：省电侦探 / 家庭能源管家

**场景**

家里电费突然变高，不知道哪个电器最耗电。Agent 结合智能插座/电表数据、电器使用习惯和电价，找出耗电黑洞，给出省电方案，并估算每月能省多少钱。

**Agent设计**

- 数据 Agent：采集功率、时长、峰谷电价。
- 分析 Agent：识别异常耗电和待机功耗。
- 建议 Agent：给出可执行省电动作。
- 报告 Agent：生成周报/月报和省钱预测。

**微电子发挥点**

- 智能插座/电表数据采集
- MQTT/串口/Modbus 协议
- 功率测量与异常检测
- 低功耗设备或边缘计算

**风险**

- 硬件依赖和数据获取难度较高。
- 若硬件来不及，可先用模拟数据集 + 一个真实智能插座做演示。

## 五、备选方向

### 老人用药与陪诊 Agent

适合强调社会价值，但药品数据和医疗合规风险较高。建议只做“提醒、记录、就医准备、家属通知”，不做诊断和用药建议。

### 宿舍/校园生活服务 Multi-Agent

最容易拿到同学反馈，适合做多 Agent 路由和工单闭环，但商业价值偏弱，需要把“校园”扩展成“园区/社区服务”才更有说服力。

### 宠物健康与喂养管家 Agent

演示可爱、传播性强，但医疗风险高，必须设置“异常转兽医”的硬规则。

## 六、选题一句话模板

> 我们为【目标用户】解决【高频生活痛点】。用户只需【输入方式】，Agent 会自动【规划/调用工具/查知识库/多Agent协作】，最终输出【可执行结果】。相比现有方案，我们能【量化改善】，并可面向【付费方】形成【商业模式】。

## 七、最终建议

- **首选**：家电说明书与故障诊断 Agent
- **稳妥备选**：家庭冰箱食材管家 Agent
- **技术黑马**：家庭能耗与电费优化 Agent
- **社会价值备选**：老人用药与陪诊 Agent
- **最容易找用户**：宿舍/校园生活服务 Multi-Agent

如果目标是“既贴近生活、又能体现 AgentArts 技术深度、还能让微电子同学有不可替代的贡献”，优先选 **家电说明书与故障诊断 Agent**。
