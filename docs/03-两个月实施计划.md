# 两个月实施计划（8 周，按 2026-10-12 起算）

> 假设：赛题2详细附件可从报名账号取得；团队每周投入约 15—20 小时/人；第8周末完成可提交版本。
> 每周末必须有可演示增量，不能只写文档或只做调研。

## 第0周（10/12—10/18）：启动与赛题解析

**目标**：确认赛题2原文和评分标准，完成选题收敛。

- A：报名/组队核对；搭 Git 仓库、目录、分支规范；整理官方手册与赛题附件。
- B：逐条拆解赛题与评分项，形成 requirement checklist；访谈 5 位目标用户。
- C：调研 AgentArts 能力边界、模型/算力配额、数据合规要求。
- 三人：用六维评分法从 3 个候选场景中选 1 主 1 备。

**周末交付**：赛题需求清单、用户调研、场景评分表、一页纸选题说明书、仓库骨架。

**Gate 0**：赛题2的详细要求、评分项、提交清单是否已全部拿到？没有则先向指导老师/组委会补齐。

## 第1周（10/19—10/25）：方案与架构

**目标**：锁定 Agent 架构和 MVP 范围。

- A：画上下文图、组件图、时序图；确定 Agent 类型与工具边界。
- B：细化用户流程、输入输出、业务指标；准备样例数据。
- C：设计知识库结构、评测集框架、领域工具接口。
- 三人：完成 Prompt/角色/工具 Schema 初稿；确定 2 个月功能冻结范围。

**周末交付**：架构设计文档、接口清单、数据与权限设计、风险清单、MVP 范围。

**Gate 1**：MVP 是否能在 3 周内端到端跑通？不能则砍功能。

## 第2周（10/26—11/1）：环境与最小链路

**目标**：打通“模型调用 + 一个工具 + 一个知识库”的最小链路。

- A：开通 AgentArts、配置模型、完成单 Agent Demo；搭后端 API。
- B：完成数据清洗脚本与知识库初版；搭建演示界面骨架。
- C：完成评测脚本骨架；准备 20 条真实测试用例。
- 三人：每日记录问题，形成环境排障文档。

**周末交付**：可运行最小 Demo、环境说明、20 条评测用例、失败日志。

## 第3周（11/2—11/8）：MVP 端到端

**目标**：完成一条主流程，做到真实输入→Agent→工具/知识库→结果→用户确认。

- A：Agent 编排、工具调用、错误处理、日志、配置管理。
- B：前端/交互联调；完善样例数据与用户提示。
- C：知识库检索接入；跑基线评测；记录准确率/时延/成本。
- 三人：邀请 3 位真实用户试用，收集问题。

**周末交付**：MVP 演示、接口文档、基线评测报告、下周迭代清单。

**Gate 2**：MVP 是否稳定跑通 10 次以上？否则本周不扩展新功能。

## 第4周（11/9—11/15）：RAG 与插件/Skill

**目标**：让 Agent 真正“懂领域、能做事”。

- A：MCP/Skill/插件接口开发；工具鉴权、幂等、失败重试。
- B：知识库切分/嵌入/检索/引用溯源；补充评测集。
- C：领域术语表、领域工具/硬件接口；做对抗与边界测试。
- 三人：开始写技术文档初稿和演示视频脚本。

**周末交付**：知识库增强版、1—3 个工具/插件、评测集 v1、文档初稿。

## 第5周（11/16—11/22）：多 Agent（按需）与安全

**目标**：只在场景确有需要时引入多 Agent，并完成安全加固。

- A：多 Agent 协作/路由；上下文压缩；成本与并发优化。
- B：Prompt 注入、隐私脱敏、版权与合规检查；更新演示脚本。
- C：幻觉检测、越权测试、工具失败测试；补充消融实验。
- 三人：完成第一次完整彩排，记录问题和答疑库。

**周末交付**：增强版 Agent、安全测试报告、第一次彩排录像、答疑库 v1。

**Gate 3**：增强版相对 MVP 是否有可量化提升？没有就回退，保留简单可靠方案。

## 第6周（11/23—11/29）：评测、消融与优化

**目标**：用数据证明方案有效。

- A：性能、成本、并发、稳定性优化；固化可复现实验。
- B：整理实验数据、图表、案例；技术文档与 PPT 成稿。
- C：跑完整评测矩阵与消融实验；输出结论和局限。
- 三人：对照评分项逐条自查，找缺口。

**周末交付**：评测报告、消融表、性能成本表、PPT v1、评分项自查表。

## 第7周（11/30—12/6）：交付物定稿与压力测试

**目标**：让评委在 5—10 分钟内看懂并相信成果。

- A：代码冻结、README、部署脚本、演示环境备份。
- B：演示视频定稿；PPT 精修；准备 3 分钟/8 分钟两版讲稿。
- C：断网、超时、模型异常、数据异常等故障演练；答辩问答。
- 三人：至少 3 次完整彩排，邀请老师/同学当“刁钻评委”。

**周末交付**：技术文档终稿、代码、演示视频、PPT、问答库、故障预案。

## 第8周（12/7—12/13）：提交与答辩

**目标**：按官方要求提交，并准备现场答辩。

- 周一：对照官方提交清单逐项核验；确认格式、命名、大小、时长。
- 周二：最终彩排，录制备份视频，准备离线演示包。
- 周三：提交材料；截图回执；备份到云端和本地。
- 周四—周五：答辩模拟、问题修正、现场分工（主讲/演示/补答）。
- 周末：休息与复盘，整理可复用模板。

**最终交付**：技术文档、代码文件、演示视频、答辩 PPT、演示环境、提交回执、复盘报告。

## 里程碑与 Gate 汇总

| 时间 | 里程碑 | 通过标准 |
|---|---|---|
| 第0周末 | 选题锁定 | 赛题/评分项清晰，主备选题确定 |
| 第1周末 | 架构锁定 | MVP 范围、接口、数据、风险明确 |
| 第3周末 | MVP 跑通 | 真实流程连续 10 次成功 |
| 第5周末 | 能力增强 | RAG/工具/多 Agent 有量化收益 |
| 第6周末 | 证据闭环 | 评测、消融、成本、安全报告齐全 |
| 第7周末 | 交付冻结 | 文档/代码/视频/PPT 可提交 |
| 第8周 | 提交答辩 | 回执、彩排、故障预案完成 |

## 每周固定节奏

- 周一 20:00：计划会，锁定本周唯一里程碑。
- 周三 20:00：风险检查，只讨论阻塞项。
- 周五 20:00：Demo Day，必须演示可运行增量。
- 周日：文档与实验记录补齐，提交回顾。
