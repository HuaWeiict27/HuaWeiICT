# 三人分工建议（2 名软件工程新生 + 1 名微电子新生）

## 一、分工原则

- 三人都是新生，不要按“一个人只写文档、一个人只写代码、一个人只做硬件”切割；必须每人都有可运行的代码产出。
- 赛题2是 Agent 软件方向，**微电子同学不应被边缘化**，最适合负责“数据/知识库/模型评测/工具插件 + 硬件或行业场景接口”，把专业背景转化为差异化优势。
- 设置两个交叉角色：每人都有“主责 + 备份”，避免单点故障。
- 所有产出进 Git：文档、代码、数据、评测、PPT、视频脚本都要版本化。

## 二、角色分配

### A：软件工程 1 —— Agent 架构与后端负责人（队长）

**主责**

- 赛题拆解、需求清单、评分项对照表。
- Agent 架构设计、工作流编排、AgentArts 配置。
- 工具调用、MCP/Skill/插件接口设计。
- 后端服务、API 封装、错误处理、日志。
- Git 仓库、分支、CI、部署、环境变量与密钥管理。

**必须交付**

- 架构文档、时序图、接口文档。
- AgentArts 可运行配置与后端代码。
- 一键复现脚本与 README。

**需要补的知识**

- Python、Git、REST API、JSON Schema。
- LLM/Agent 基础、Function Calling、MCP。
- 华为云 AgentArts、IAM、API 网关、FunctionGraph。
- 基本测试与可观测性。

**学习资源**

- 华为云 AgentArts/ModelArts 文档。
- Anthropic《Building effective agents》。
- OpenAI Agents SDK 文档、MCP 规范。
- FastAPI + pytest + ruff 官方文档。

### B：软件工程 2 —— 产品、数据与前端/演示负责人

**主责**

- 用户调研、场景定义、价值主张、竞品分析。
- 数据采集、清洗、脱敏、标注、知识库原始材料整理。
- 评测集构建、实验记录、指标看板。
- 前端/低代码交互、演示脚本、视频剪辑。
- 技术文档、答辩 PPT、路演材料。

**必须交付**

- 用户调研报告、场景评分表、一页纸方案。
- 数据集与知识库构建脚本、评测集。
- Demo 界面、演示视频、答辩 PPT。

**需要补的知识**

- 需求分析与用户访谈、产品原型。
- Python 数据处理、正则、JSON/CSV、Pandas 基础。
- RAG 数据管道、Embedding、向量数据库。
- 技术写作、信息设计、视频剪辑。

**学习资源**

- 《精益创业》《用户体验要素》。
- LangChain/LlamaIndex 文档中的 RAG 教程。
- RAGAS/DeepEval 评测文档。
- 往届创新赛答辩视频与获奖项目介绍。

### C：微电子 —— 知识库、模型评测与硬件/行业工具负责人

**主责**

- 把微电子/硬件/行业知识转化为 Agent 的领域知识库与工具能力。
- 负责知识库切分、检索、引用溯源、领域术语表。
- 负责模型/Agent 评测：准确性、幻觉、工具失败、边界用例。
- 负责硬件/传感器/行业数据接口或模拟器；若赛题允许，接入真实设备或数字孪生。
- 负责性能、成本、稳定性测试与安全合规检查。

**必须交付**

- 领域知识库与术语表。
- 评测脚本、基线报告、消融实验表。
- 硬件/行业工具插件或模拟器代码。
- 安全与成本检查表。

**需要补的知识**

- Python（重点：数据处理、API、异常处理）。
- RAG、Embedding、向量检索、评测指标。
- 微电子/硬件接口：串口、MQTT、传感器、边缘设备基础。
- 华为云 OBS、FunctionGraph、API 网关；MCP/Skill 开发。

**学习资源**

- 《动手学深度学习》选读（只学与场景相关的部分）。
- LangChain/LlamaIndex RAG 教程。
- MQTT、串口通信、ESP32/树莓派入门（如场景需要）。
- 华为云 IoT/边缘计算文档（如场景需要）。
- RAGAS/DeepEval 文档。

## 三、RACI 简表

| 事项 | A 软工1 | B 软工2 | C 微电子 |
|---|---|---|---|
| 赛题解析/需求 | R | A | C |
| 架构设计 | A/R | C | C |
| AgentArts 配置 | A/R | C | C |
| 数据/知识库 | C | A | R |
| 模型评测 | C | A | R |
| 插件/MCP/Skill | A/R | C | R |
| 前端/Demo | C | A/R | C |
| 文档/PPT/视频 | C | A/R | C |
| 硬件/行业接口 | C | C | A/R |
| 项目管理/Git | A/R | C | C |
| 答辩 | R | R | R（三位都上） |

R=负责执行，A=最终负责，C=协作/咨询。

## 四、协作机制

- 每日 15 分钟站会：昨天完成、今天目标、阻塞项。
- 每周一锁定“本周唯一里程碑”，周五必须能演示。
- 所有代码走 Pull Request；至少 1 人 Review。
- 所有实验必须记录配置、数据、结果、结论，避免“凭感觉调参”。
- 每两周请指导老师做一次评审，重点看评分项覆盖度和风险。
- 建立“失败日志”：记录失败案例、原因、修复、验证结果。
